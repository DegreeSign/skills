# Webpack build and folder structure

A reusable TypeScript library layout with a dual browser + Node webpack build. Adjust names to the package.

## Choose the target: browser, Node, or both

Decide from the package's nature and its code before writing the config. Inspect what `src/` actually touches.

**Browser only** when the code depends on browser APIs:
- `window`, `document`, `navigator`, `localStorage`, `indexedDB`, `fetch`, DOM events, CSS/DOM types.
- No `node:` built-ins or Node globals.

**Node only** when the code depends on Node:
- `node:fs`, `node:path`, `node:http`, `node:crypto`, `process`, `__dirname`/`__filename`, streams, native addons.
- Server SDKs, CLI tools, file system utilities, cache/storage backends.

**Both** when the code is environment-agnostic:
- Pure logic, data transforms, string/date/math helpers, types, or HTTP that works with `fetch` on each platform.
- Isolate any tiny platform difference behind a runtime check (for example `typeof window !== 'undefined'`) or a resolved fallback (for example aliasing a `fetch` polyfill for Node), then ship both bundles.

Rules:
- If any dependency is browser- or Node-only, do not ship that target.
- Never polyfill Node built-ins into a browser bundle; split the build instead.
- When unsure, ship Node only, then add the browser build once the code is confirmed free of Node APIs.
- A package that targets the web must set `browser` in `package.json` and get CDN version bumps in the README on release.

## Folder structure

```
src/
  index.ts        public entry: re-export the public API
  types.ts        shared types
  code/           implementation modules (split into feature folders as it grows)
dist/             committed build output
  index.d.ts
  node/mylib.node.min.js
  browser/mylib.min.js
package.json
tsconfig.json
webpack.config.ts
README.md
ChangeLog.md
LICENSE
```

- Everything importable by consumers is re-exported from `src/index.ts`; keep it as the single entry point.
- Put implementation in modules/folders under `src` and re-export the public surface from `index.ts`.
- Never hand-edit `dist/`; it is generated by the build and committed.

## package.json

```json
{
  "main": "dist/node/mylib.node.min.js",
  "module": "dist/node/mylib.node.min.js",
  "browser": "dist/browser/mylib.min.js",
  "types": "dist/index.d.ts",
  "files": ["dist/"],
  "scripts": {
    "build": "webpack"
  }
}
```

- `main`/`module` point at the Node build, `browser` at the browser build, `types` at the emitted declarations.
- `files: ["dist/"]` ships only the build output.
- A shared build-helper package in dev deps can wrap this config, but a hand-written `webpack.config.ts` is fine and dependency-free.

## tsconfig.json

```json
{
  "compilerOptions": {
    "target": "es2022",
    "module": "CommonJS",
    "moduleResolution": "node10",
    "resolveJsonModule": true,
    "declaration": true,
    "outDir": "dist",
    "esModuleInterop": true,
    "forceConsistentCasingInFileNames": true,
    "strict": true,
    "skipLibCheck": true
  },
  "include": ["src/**/*"],
  "exclude": ["node_modules"]
}
```

- `declaration: true` emits `dist/index.d.ts`; keep `types` in `package.json` pointing at it.
- `outDir: "dist"` is overwritten by webpack for the bundles but is what emits the declarations.

## webpack.config.ts (browser + Node)

```ts
import * as path from 'path';
import * as webpack from 'webpack';
import TerserPlugin from 'terser-webpack-plugin';

const commonConfig: webpack.Configuration = {
    entry: `./src/index.ts`,
    resolve: {
        extensions: [`.ts`, `.js`],
    },
    module: {
        rules: [
            {
                test: /\.ts$/,
                use: `ts-loader`,
                exclude: /node_modules/,
            },
        ],
    },
    plugins: [
        new webpack.BannerPlugin({
            banner: `/*! MIT License. https://opensource.org/licenses/MIT */`,
            raw: true,
        }),
    ],
    optimization: {
        minimize: true,
        minimizer: [new TerserPlugin()],
        usedExports: true,
        sideEffects: false,
    },
    mode: `production`,
};

const browserConfig: webpack.Configuration = {
    ...commonConfig,
    target: `web`,
    output: {
        path: path.resolve(__dirname, `dist/browser`),
        filename: `mylib.min.js`,
        library: `MyLib`,
        libraryTarget: `umd`,
        globalObject: `this`,
    },
};

const nodeConfig: webpack.Configuration = {
    ...commonConfig,
    target: `node`,
    resolve: {
        ...commonConfig.resolve,
        mainFields: [`module`, `main`],
        conditionNames: [`import`, `default`],
        aliasFields: [],
        preferRelative: true,
    },
    output: {
        path: path.resolve(__dirname, `dist/node`),
        filename: `mylib.node.min.js`,
        libraryTarget: `commonjs`,
        globalObject: `typeof globalThis !== 'undefined' ? globalThis : (typeof self !== 'undefined' ? self : this)`,
    },
    node: {
        __dirname: false,
        __filename: false,
    },
};

module.exports = [browserConfig, nodeConfig];
```

For a Node-only package, `module.exports = nodeConfig` (single config, no browser build).

## Plugins

- `ts-loader` compiles TypeScript; `exclude: /node_modules/`.
- `TerserPlugin` minifies; `usedExports: true` and `sideEffects: false` enable tree-shaking.
- `BannerPlugin` prepends the license banner.
- Add `clean-webpack-plugin` when you want `dist/` cleared before each build (omit it while `dist/` is committed and only rebuilt deliberately).
- Add `webpack-bundle-analyzer` (`BundleAnalyzerPlugin`) only when investigating bundle size; it opens a report on every build.
