# Tickets

## The ticket file

- The ticket file holds the full list of all tickets. Add, edit or remove tickets there when requested.
- Keep each ticket as a one-line entry with an emoji tag and a short description.
- Only use an emoji that already appears in the file. Never introduce a new one.
- Keep description sentences short and concise.
- A new ticket you create is one line, no full stop, under about ten words.

## Shorthand

- A reference like `L4` means the line number in the ticket file (line 4), not an ID or a position in a task list. Read that line to find the ticket.

## Status

- Ticket colour blocks denote status: black for all tasks, yellow for in progress, green for done.
- When moving a ticket to the done section, place it at the top of the done list.

## Detail docs

- When a ticket needs detailed technical notes for future implementation, write them in the details folder, one file per feature, and link the ticket to it with a relative link.
- Detail docs are simple implementation references: steps, files and verification. Never speculation or a completed-work log.
